# Redis 分布式锁 - 流程图

## 加锁流程

```
┌──────────┐                                    ┌──────────┐
│  Client  │                                    │  Server  │
└────┬─────┘                                    └────┬─────┘
     │                                               │
     │  POST /api/v1/lock/acquire                    │
     │  { "resource": "order:10086", "ttl": 10 }     │
     │ ─────────────────────────────────────────>    │
     │                                               │
     │                           生成 owner = UUID()  │
     │                                               │
     │                   SET lock:order:10086 <uuid> │
     │                       NX EX 10               │
     │                   ─────────────────────> Redis │
     │                                               │
     │            ┌──────────────────────────────────┤
     │            │          Redis 返回 OK            │
     │            │     (key 不存在，写入成功)          │
     │            └──────────────────────────────────┤
     │                                               │
     │ <─────────────────────────────────────────── │
     │  { code:0, data: { resource, owner, ttl } }   │
     │                                               │
     │            ┌──────────────────────────────────┤
     │            │         Redis 返回 nil            │
     │            │     (key 已存在，写入失败)          │
     │            └──────────────────────────────────┤
     │                                               │
     │ <─────────────────────────────────────────── │
     │  { code:40009, message:"resource is locked" } │
     │                                               │
```

## 解锁流程（Lua 原子操作）

```
┌──────────┐                                    ┌──────────┐
│  Client  │                                    │  Server  │
└────┬─────┘                                    └────┬─────┘
     │                                               │
     │  POST /api/v1/lock/release                    │
     │  { "resource": "order:10086" }                │
     │ ─────────────────────────────────────────>    │
     │                                               │
     │               从请求上下文取 owner_token        │
     │                                               │
     │                   EVAL Lua 脚本               │
     │                   ─────────────> Redis        │
     │                                               │
     │   Lua: if GET(key) == owner then DEL(key)     │
     │         └─ 原子执行，不会被其他命令打断          │
     │                                               │
     │            ┌──────────────────────────────────┤
     │            │         Lua 返回 1               │
     │            │     (value 匹配，删除成功)          │
     │            └──────────────────────────────────┤
     │                                               │
     │ <─────────────────────────────────────────── │
     │  { code:0, message:"lock released" }          │
     │                                               │
     │            ┌──────────────────────────────────┤
     │            │         Lua 返回 0               │
     │            │   (value 不匹配或 key 不存在)       │
     │            └──────────────────────────────────┤
     │                                               │
     │ <─────────────────────────────────────────── │
     │  { code:50000, message:"release failed" }     │
     │                                               │
```

## 为什么解锁必须用 Lua 脚本

```
┌─────────────────────────────────────────────────────────┐
│  错误做法：GET + DEL 两步操作（非原子）                    │
│                                                         │
│  客户端 A              Redis               客户端 B       │
│  GET lock:key  ─────>  "uuid-A"                         │
│  （比对成功，准备删）                                     │
│                         TTL 到期，key 自动删除            │
│                                          SET lock:key    │
│                                          "uuid-B"        │
│  DEL lock:key  ─────>  删除了 uuid-B ！                  │
│                                                         │
│  结果：A 误删了 B 的锁                                    │
└─────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────┐
│  正确做法：Lua 脚本（原子执行）                            │
│                                                         │
│  EVAL "if redis.call('GET',KEYS[1])==ARGV[1]            │
│         then return redis.call('DEL',KEYS[1])           │
│         else return 0 end"                              │
│       1 lock:order:10086 <owner-uuid>                   │
│                                                         │
│  GET 和 DEL 在同一个 Lua 脚本中原子执行，中间不会被打断   │
└─────────────────────────────────────────────────────────┘
```

## 并发争抢流程

```
                        ┌──────────┐
                        │  Redis   │
                        └────┬─────┘
                             │
  协程 1  ─── SET NX ──────> │ ──> OK   (获取成功)
  协程 2  ─── SET NX ──────> │ ──> nil  (获取失败)
  协程 3  ─── SET NX ──────> │ ──> nil  (获取失败)
  协程 4  ─── SET NX ──────> │ ──> nil  (获取失败)
  协程 5  ─── SET NX ──────> │ ──> nil  (获取失败)
                             │
  协程 1 持有锁，执行业务逻辑 (hold_ms)
                             │
  协程 1  ─── Lua DEL ─────> │ ──> 1    (释放成功)
                             │
```

**结论：** N 个并发请求中，有且仅有 1 个能获得锁，其余立即失败返回。这正是分布式锁"互斥性"的核心体现。

## TTL 过期自动释放

```
时间轴：

t=0s    客户端 A 获取锁（TTL=10s）
        Redis: SET lock:res uuid-A EX 10

t=5s    客户端 A 因异常崩溃，未能主动释放

t=10s   Redis TTL 到期，自动删除 lock:res
        ↓
        锁自动释放，其他客户端可以重新获取

t=11s   客户端 B 获取锁成功
        Redis: SET lock:res uuid-B EX 10
```

**死锁场景已消除：** 即使持有锁的进程崩溃，TTL 到期后锁会自动释放，系统不会陷入永久阻塞。
