## 手动发布流程

```
┌──────────┐     POST /api/v1/mqtt/publish      ┌──────────┐
│  Vue 前端 │────────────────────────────────────→│ Go 后端   │
│ (手动表单) │←────────────────────────────────────│ (Handler) │
└──────────┘     { code:0, data:{...} }          └────┬─────┘
                                                      │
                                          MQTTClient.Publish()
                                                      │
                                                      ↓
                                              ┌───────┴──────┐
                                              │   Mosquitto   │
                                              └───────┬──────┘
                                                      │
                                          Subscribe 回调触发
                                                      │
                                                      ↓
                                              SSEBroker.Publish()
                                                      │
                                                      ↓
                                              前端 EventSource 收到
                                              mqtt_message 事件
```

## Topic 结构

```
sensors/
├── temperature     ← 温度数据（单个 SensorData JSON）
├── humidity        ← 湿度数据（单个 SensorData JSON）
├── pressure        ← 气压数据（单个 SensorData JSON）
├── all             ← 聚合数据（三路数据合并 JSON）
└── test            ← 手动发布测试
```

## 传感器数据格式

```json
{
  "device_id": "sensor-001",
  "value": 23.5,
  "unit": "°C",
  "sensor_type": "temperature",
  "timestamp": "2026-06-30T10:00:00Z"
}
```

## SSE 心跳机制

- 后端每 30 秒发送 `heartbeat` 事件，防止代理（Nginx）闲置超时断连
- 浏览器 EventSource API 支持自动重连（断线后按一定间隔重试）
- Nginx 已配置 `proxy_read_timeout 3600s` 保障长连接

## 关键设计决策

| 决策 | 原因 |
|------|------|
| SSE 而非 WebSocket | 数据流是单向的（Broker → 前端），SSE 更简单且支持自动重连 |
| 全局 SSEBroker | 单一 fan-out 分发点，多个前端订阅者共享同一 MQTT 客户端连接 |
| 环形历史缓冲 | 保留最近 100 条消息，新订阅者可以回溯最近的消息 |
| `select + default` 防阻塞 | Publish 时对慢客户端通道使用非阻塞发送，避免单个慢客户端拖垮整个广播 |
